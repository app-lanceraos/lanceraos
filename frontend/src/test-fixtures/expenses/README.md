# Expenses test fixtures

Tracked on purpose (the `*.test.*` files are gitignored). Every file here was **generated from the real views and
serializers**, not typed by hand: a throwaway user was created inside one database transaction, the expenses were created
through the real service (`expense_services.create_expense`, so each rate is frozen exactly as in production), the real
endpoints were called through Django's test client with a real minted access cookie, the responses were saved, and the
transaction was rolled back. The rolled-back run left the database exactly as it found it (the same row counts for
`expenses`, `payments`, `users`, sessions, audit rows, request-log rows and exchange-rate snapshots, before and after).

| File | Endpoint | What it holds |
|------|----------|---------------|
| `list.sample.json` | `GET /api/expenses/` | Fourteen expenses, newest first: a `fees` one with a vendor and a description; a non-deductible one (`is_deductible: false`); PKR ones with `rate_basis` `exact`, `nearby` and `estimated`; USD ones, one with an empty vendor; a GBP one with `rate_basis: "none"`; and one whose vendor is `=SUM(1+1) <b>x</b>` with a description of `<script>alert(1)</script>` (hostile text that must be shown as plain text) |
| `summary.sample.json` | `GET /api/expenses/summary/` | The user's profile currency is USD. Every period, a non-null `month_change_pct`, ten `by_category` rows with different totals and the server's labels, 12 zero-filled months, `deductible_total` smaller than `total`, `estimated_count: 1` and `unconverted_count: 1` |
| `summary-empty.sample.json` | `GET /api/expenses/summary/` | The same endpoint for a user with no expenses (zeros, `month_change_pct: null`, empty `by_category`) |
| `create-with-duplicates.sample.json` | `POST /api/expenses/` | A 201 body with `possible_duplicates` (same currency, exact amount and category within 3 days) |
| `currencies.sample.json` | `GET /api/expenses/currencies/` | The distinct currencies the throwaway user had |
| `categories.sample.json` | (none) | `[{value, label}]` generated by importing `EXPENSE_CATEGORY_CHOICES` from `apps/payments/constants.py`. The frontend test that compares `EXPENSE_CATEGORIES` with this file is what makes a category change on the server fail a test here |

The GBP expense in `list.sample.json` has `rate_basis: "none"`. It was created normally and then, **inside the rolled-back
transaction**, updated to `rate_to_usd=None, rate_basis='none', exchange_rate_snapshot=None`. That is a valid stored state
(a currency for which no exchange rate was ever captured); the API cannot produce it for a new expense any more, so it
cannot be generated by calling the endpoints alone.

Dates are absolute calendar strings from the day they were generated (8 November 2026). Tests that need "today" must
not rely on them; they use the values only for shape, ordering and money.

To regenerate: re-run the generator (a Django script that builds the same data inside `transaction.atomic()` and raises to
roll back), then review the diff. Do not edit these files by hand.
