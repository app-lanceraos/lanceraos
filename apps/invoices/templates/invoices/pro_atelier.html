{% comment %} apps/invoices/templates/invoices/pro_atelier.html 20-Template Import, Batch 5 (15 September 2026) — ported from proTemplates.html's "Atelier" prototype (tpl-atelier). Boutique-editorial design: a tinted paper page background, a persistent left rail (pure branding — logo, business name, a small styled title line, an address/ email footer), a huge serif doc title, and numbered content sections. Real, confirmed WeasyPrint limitation found during this batch's own verification (Part 0/1): the prototype's own `.atl-rail-mid` uses `writing-mode: vertical-rl` to run its title/number text vertically along the rail's spine. This WeasyPrint version does not support `writing-mode` at all (a real "unknown property" console warning, not a missing vendor prefix or a typo) — the property is silently ignored, so a naive port would ship `transform: rotate(180deg)` alone, producing upside-down (never vertical) horizontal text with no visual reason for the rotation. Fixed by dropping both declarations and rendering this line as plain, normally-flowing horizontal text instead (still visually distinct via letter-spacing/uppercase/accent color) — see `.atl-rail-mid`'s own comment. Real, preserved deviation #1: the persistent rail. The prototype's own `renderFull(inv, pages)` only renders the rail (`atl-shell`/`atl-rail`) on page 1 — continuation pages get a plain `continuationHeader` instead. Per free_minimal.html's own established precedent (Batch 3, itself mirroring production modern.html's own sidebar), this page-1-only treatment is a pagination-SIMULATION artifact (the prototype's `pages` array + per-chunk JS rendering has no equivalent in a real, continuously- flowing Django template) — not a real design requirement. Ported via the same proven `position: fixed` technique, which repeats the rail on every real page automatically, a strict improvement over the prototype's own page-1-only limitation, not a deviation from it. Real, preserved deviation #2: `body{ background: var(--paper) }` — a tinted page background across the WHOLE page (matching pro_studio.html's/ pro_signature.html's/pro_prestige.html's own real deviation, Batch 4) — ported using the same `@page margin: 0 0 {cond} 0` + inner-padding technique those 3 already established, for the identical reason (a real, nonzero `@page` margin would leave WeasyPrint's own margin-box area painted the page's default WHITE, not the body's tint). Real, preserved deviation #3: numbered content sections (`section()` in the prototype, a 2-digit index — "01", "02", etc. — beside each major content block). The prototype increments this counter only for non-empty sections, which would require genuinely dynamic per-request numbering in a real template; simplified here to the fixed sequence Parties/Items/Summary/Footer always renders as (01-04) — in real usage every one of these 4 sections always has SOME real content (the From party always has a business name at minimum; Bill To falls back to "No client yet"; items always render, even as the empty-fallback row), so the prototype's own dynamic skip-when-empty behavior has no real-world case where it would ever actually fire differently from this fixed sequence. Real, preserved deviation #4: Terms renders as a single, separate trailing paragraph BELOW the whole footer grid (`atl-terms`), not combined with Notes in the standard `notes-terms` box — the prototype's own `renderFull` pushes Notes into the SAME footer-grid row as Payment/ Signature, then appends Terms as its own standalone paragraph after that entire grid. Written as one-off inline markup (not a `notes_terms.html` change) — the same "no second real consumer, write it inline" precedent `pro_editorial.html`'s own independent-colophon-columns deviation and `free_freelancer.html`'s "thanks box" (Batch 2) both already established. Real, preserved deviation #5: the Summary section splits totals exactly like `pro_editorial.html` does (subtotal/tax/discount separate from a distinct "Total due" callout) — written inline for the same reason Editorial's own split is inline, not a `totals.html` mode change (see that template's own docstring).
