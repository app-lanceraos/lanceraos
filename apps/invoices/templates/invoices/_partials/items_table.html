{% comment %} apps/invoices/templates/invoices/_partials/items_table.html Line items table. Direct port of the prototype's itemsTableHtml(inv, items), including the empty-items fallback row ("No line items on this invoice") — Django's own {% for %}/{% empty %} handles that natively rather than the prototype's manual length check. The SKU column is preserved structurally (an optional `with show_sku=True` param a future caller could pass) but Part 0c of the 20-Template Import (14 September 2026) confirmed InvoiceItem has no `sku` field at all (verified directly against apps/invoices/models.py) — nothing sets show_sku today, so the column never renders, gracefully, same as every other conditional in this codebase when the underlying data doesn't exist. Optional `with embed_totals=True` (20-Template Import, Batch 2, 14 September 2026) — a real, preserved deviation found in the prototype's own "Compact" design (`freeTemplates.html`'s `compact.renderItems`): subtotal/tax/discount/total-due render as a `` INSIDE this table instead of the standard separate `.inv-totals` block `totals.html` renders — Compact's own "dense, many items" design has no separate totals block at all. When `embed_totals` is set, the caller should NOT also include `totals.html` (it would duplicate the total). The PKR/secondary- currency conversion line (`invoice.client_currency_conversion`) is included here too as a final tfoot row, for the same reason `totals.html` always includes it — Compact's own tfoot in the prototype predates that requirement and has no equivalent, so this generalizes it forward rather than losing the feature for this one template. Requires `invoice` in context (uses invoice.items.all and invoice.currency_symbol). {% endcomment %} {% load humanize %}
